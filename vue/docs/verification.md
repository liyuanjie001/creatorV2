## 本轮验证的行为

- 窗口管理删除内容报表，查看数据跳转后保留项目、窗口与平台筛选。
- 数据分析提供总览、账号监测、内容明细与四个维度的对比，范围和筛选写入地址。
- 同一平台账号关联多个窗口时，账号与视频去重，对比合计不翻倍。
- 共用账号在任务中只选择一次，支持切换执行窗口。
- 真实的 0、未采集、历史不足、采集失败与采集能力未验证分开显示。
- 总览标明可用内容覆盖比例，历史不完整的内容不参与对比。
- 粉丝周增长使用独立的粉丝快照，覆盖负增长与历史不足。
- 运营阶段手动维护并持久化，不改变登录状态。登录恢复也不会自动冒充采集成功。
- 首次采集不补造历史，旧绑定与登录恢复记录可继续读取。
- 账号详情可进入视频详情，管理窗口的跳转不会被查询参数监听拉回分析页。
- 重置演示清理运营标签及绑定，保留访问锁和妙记。

原有的全局密码锁、15 个页面挂载、13 个项目栏目、创作生成、商品切换、素材搜索、灵感与妙记保存等回归测试继续通过。

## 浏览器检查

通过现有 Chrome 标签页检查了窗口管理的新结构、数据总览、共用 YouTube 账号的窗口对比、账号监测、运营阶段刷新恢复，以及账号详情进入视频详情。

浏览器中的对比确认两个窗口各显示 14,939 播放，去重合计仍为 14,939。YouTube 视频详情展示“采集能力未验证”和缺少首小时快照的原因，不展示流量池或推荐状态。

检查结束时控制台没有 error 或 warn。保留用户原有的三个同步项目，测试用的运营阶段恢复到未分阶段，页面留在数据分析总览。

## 演示边界

所有 Roxy 绑定、采集、登录恢复和报表均为前端演示，没有运行真实账号采集或网站归因。高级指标示例不构成平台采集能力承诺。

单独的[数据分析改造原因与指标边界](analytics-design-rationale.md)记录每项报表的取舍、数据条件、官方资料，以及未来官网进站与成交统计需要的工作。
