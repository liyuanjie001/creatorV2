# 为什么简化窗口管理，并调整数据分析设计

本文记录 2026-10-22 对 `demo2/reference` 的评审与 Vue 演示改造依据，供产品、设计和后续采集开发共用。评审查看了参考稿的数据分析主页面、账号详情和视频详情，并核对下文列出的官方资料。本文区分“平台存在某种数据”“目标账号后台可见”和“本产品已验证能稳定采集”，三者不能画等号。

当前版本仍为纯前端演示，没有连接真实 Roxy、社媒后台或网站统计。页面上的数值标记为演示数据，账号和内容中的未采集、历史不足、平台不支持与采集失败也是演示场景。文档核验不能替代真实账号与采集程序的联调。

## 窗口管理与数据分析为什么分开

窗口管理解决连接和执行环境问题：绑定 Roxy、勾选项目、同步窗口、确认账号身份、检查登录与进入采集入口。数据分析解决内容表现问题：账号、视频、趋势、画像、筛选和对比。两页都提供播放与互动报表，会产生重复入口、筛选不同步和两套统计口径。

因此，内容报表统一进入数据分析。窗口列表和项目详情保留“查看数据”入口，并携带项目、窗口、平台筛选。窗口管理只保留窗口数、已识别账号数、登录待恢复等管理信息。

账号也不能以窗口编号作为唯一身份。同一个平台账号可以关联多个窗口；其视频、播放和账号数应按平台账号身份及视频 ID 去重。窗口对比的两行可能引用同一批视频，去重合计不一定等于逐行相加。当前演示用 GlowUp 官方 YouTube 在两个窗口关联的场景验证这一点。发布任务同样只为这个账号发布一次，并选择一个执行窗口。

## Roxy 能提供什么，不能据此承诺什么

[Roxy 官方接口文档](https://roxybrowser.cn/docs/api-documentation/api-endpoint.html)提供团队项目、窗口、配置、账号库和浏览器操作。账号库中的用户名与 Cookies 是配置数据，不是平台当前登录身份的证明。

在真实接入中，仍需通过浏览器中的平台页面确认登录、账号 ID 和选中的频道，再读取其可见内容或后台。Roxy API Key 不是 TikTok、YouTube、Instagram 的通用数据授权。云端也不能直接访问用户电脑的 `127.0.0.1`，本地采集端需要运行且能连接 Roxy。

平台后台存在数据，也不意味着网页端一定提供；不同账号类型、权限、地区、内容类型、样本量和时间范围都可能影响结果。当前没有对用户的真实账号完成这些验证，因此高级指标只能作为条件示例，不能承诺所有平台都能获得。

## 参考稿中哪些报表没有纳入，为什么

| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |

| 完播、留存、互动达到固定阈值就继续推流                     | 阈值来自演示假设，未经目标账号、内容类型及推荐系统验证。满足三个数值也不能证明后续一定获得推荐。                       | 移除推荐阈值和推流结论。                                                         |
| 停止推流后数据冻结、没有继续监测价值                       | 播放增长放缓不等于平台确认停止分发，也不能据此断言之后没有搜索、分享或其他访问。                                       | 展示采集时间及实际区间趋势，不展示官方停止推流判断。                             |
| 同池均值与固定行业基准                                     | 没有可核验的数据源、样本范围、时间、平台及内容定义，不能作为可靠比较基线。                                             | 本轮移除。播放中位数仅基于当前账号的可用视频样本，标注 N 和时间范围。            |
| 播放下降或“去同质化闸门”直接认定限流                       | 下降可能来自发布节奏、内容、时间或采集失败。演示中的规则无法证明平台处罚。                                             | 不给账号标注未经证实的限流原因。数据提醒只提示已知登录、采集和历史覆盖问题。     |
| 5A 人群推断                                                | 聚合的播放、评论、分享不能识别同一批用户的完整行为，也无法证明各人群阶段的人数。                                       | 本轮移除 5A 模型与人群规模。                                                     |
| 评论、主页访问直接等同“询问人群”；分享、关注等同“拥护人群” | 这些是行为次数或不同口径的统计，可能重复，同一人也可能跨多个行为；不能直接作为去重人群标签。                           | 保留有来源的原始指标，不推导未经验证的人群身份。                                 |
| 号损率                                                     | 登录失效、采集失败与账号被封禁是不同事件。没有明确的损失定义、事件记录、分母和观察区间。                               | 本轮不展示号损率，也不把登录异常当作封号。                                       |
| 自动判断测试期、放量期并给出预算系数与加投建议             | 运营阶段是团队业务定义，不能由播放量证明；预算建议还缺少成本和转化依据。                                               | 保留“未分阶段、测试期、放量期、暂停”人工标签，与登录状态分开。移除自动加投判断。 |
| 曝光、完播、互动、点击、成交连成一个精确漏斗               | 这些聚合值可能来自不同周期、平台和人群，并非已关联的同一组用户事件。互动也不一定发生在完播之后。                       | 本轮只做内容分析，移除转化漏斗。                                                 |
| 统一将“曝光”与“播放”写为同一个指标                         | 曝光、触达与播放定义不同，跨平台播放也不等于去重观众。                                                                 | 当前统一展示播放及赞评；不把它们改称曝光或人数。                                 |
| 把粉丝画像、视频观众画像及内容兴趣标签混用                 | 粉丝不是每条视频的全部观众；内容主题也不能证明观众的兴趣标签。                                                         | 账号详情单独展示标记为示例的粉丝画像。未验证的画像不补造。                       |
| 用发布时间分布替代粉丝活跃时段                             | 发文时间、内容互动时间与观众在线时间是不同数据。                                                                       | 本轮不展示未经验证的活跃时段报告。                                               |
| 将“最近活跃”统一显示为账号的社媒活跃状态                   | 浏览器打开时间、脚本执行时间、内容发布时间都不等于平台记录的账号最后活跃时间。                                         | 用明确的最近采集时间与内容发布时间。                                             |

这些调整基于以下可核验资料，而不是认定平台永远不会提供某项功能：

- [TikTok 视频对象](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-object)列出视频基础字段和播放、点赞、评论、分享，不包含本演示所说的流量池、同池均值或推流状态。
- [TikTok 推荐说明](https://newsroom.tiktok.com/how-tiktok-recommends-videos-foryou?lang=en-AU)描述多种推荐信号，不能据此推出参考稿的固定阈值与冻结机制。
- [TikTok Studio 说明](https://support.tiktok.com/en/using-tiktok/creating-videos/tiktok-studio?invalid_lang=ja)区分内容、观众和粉丝分析，并提示网页端工具有限。

## 哪些指标保留，但需要条件

| 指标                                 | 数据条件与当前演示口径                                                                           |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 播放、点赞、评论、发布时间和视频时长 | 优先采集的内容指标。页面保留来源与采集时间，不承诺每个平台和内容类型都具备所有字段。             |
| 区间增量与近 7／30／90 天趋势        | 需要平台历史报表或连续快照。刚同步的内容不能凭当前累计值重建过去。缺少历史时显示“历史不足”。     |
| 周涨粉                               | 需要完整的粉丝历史。演示给出快照差值示例；未采集或历史不足时不显示虚假的 0。                     |
| 发布后 1 小时播放                    | 需要对应时点记录或足够细的历史。旧视频的累计播放不能倒推，缺记录显示“未采集”。                   |
| 播放中位数                           | 基于当前时间范围的完整视频样本计算，标注 N。存在缺失样本时不提供有偏的中位数。                   |
| 前 3 秒留存、完播率、平均观看时长    | 各自有独立定义。当前只给明确标记的能力示例，其余平台展示未验证或不支持，不用一个指标替代另一个。 |
| 平台主页访客                         | 是社媒平台内的主页访问，不是官网进站。演示注明来源与口径。                                       |
| 画像                                 | 是满足平台条件后的汇总报告，不是单个观众的身份或兴趣识别结果。                                   |

[YouTube 指标定义](https://developers.google.com/youtube/analytics/metrics)区分平均观看百分比与观看时长，不能直接把平均观看百分比叫作完播率。[留存说明](https://support.google.com/youtube/answer/9314415?hl=en)也说明报告范围与处理延迟。

[Meta 的 Instagram 官方集合](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-af579d08-121e-4897-8f45-5fd41ace49df)说明专业账号与权限条件。[X 指标](https://docs.x.com/x-api/fundamentals/metrics)和[LinkedIn 指标](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/members/post-statistics)另有自身字段、权限与聚合限制。这些文档证明不同平台有不同能力，不能证明仅凭 Roxy 登录就已经验证了采集实现。

## 为什么进站、订单与 ROAS 本轮暂不展示

本轮已确认只做内容分析，不增加网站接入、链接生成、订单与广告数据整合。因此页面不展示点击、进站、成交、转化率或 ROAS 卡片，也不使用示例值暗示网站已经接入。

以后统计自有官网需要分别考虑：

- 只统计总访客，不强制生成新 URL，但网站需要统计埋点。
- 要区分平台、账号和活动，可给原落地页生成带 UTM 参数的版本。UTM 标记来源，不负责计数；不必新建页面或短链域名。见 [Google 的 UTM 说明](https://support.google.com/analytics/answer/10917952?hl=en-GS)。
- 点击次数、页面访问、会话和独立访客不等价。短链日志还可能包含预览请求和重复点击，不能代替网站访客统计。独立访客受统计工具的身份识别方式影响。见 [访客指标定义](https://support.google.com/analytics/answer/12253918?hl=en)。
- 账号主页共用一个链接，通常只能追踪到账号或入口。不能把官网流量按播放比例硬分配给每条视频；更换主页链接也会影响旧内容引来的访问。
- 链接需要有实际可点击的位置。[YouTube 链接说明](https://support.google.com/youtube/answer/13748639?hl=en)明确 Shorts 描述和评论中的普通 URL 不可点击。
- 订单需要网站或店铺记录购买事件和订单 ID，并考虑重复上报、退款以及来源参数是否延续到结账。见 [购买与退款事件](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce)。
- 跨域结账需要单独处理用户和会话关联。见 [跨域测量](https://support.google.com/analytics/answer/10071811?hl=en-GBFIND)。
- ROAS 需要广告花费和归因收入，订单数本身不够。自然内容表现也不能直接获得一个有意义的广告回报率。

上述能力需要网站数据和独立的归因设计。未来即使通过已登录浏览器读取网站统计后台，网站本身仍然必须先有统计数据，Roxy 不会自动记录其他访客在官网的行为。

## 如何避免演示值被误认为真实数据承诺

当前数值统一标记为演示数据，指标提示说明来源和采集时间。未采集、历史不足、采集失败、未验证平台指标与真实的 0 分开显示。

总览允许汇总可用视频，但显示覆盖比例；不把缺失部分默认为 0。对比分析要求所选项目具有完整区间数据，避免把不完整样本当成可比结果。去重合计按视频 ID 计算。运营阶段手动保存，不会自动触发发布、投放或平台操作。

后续纳入高级指标前，需要记录真实来源页面或接口、账号类型和权限、指标定义、采样周期与历史范围，并用目标账号完成采集验证。具备这些依据后，可以扩展当前状态模型，而不必继续依赖演示假设。
