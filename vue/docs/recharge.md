# 充值与购买账号演示

个人中心展示“我的套餐＋剩余积分”权益卡，可升级套餐、积分充值或打开当前版本权益详情。套餐和积分充值移至独立“套餐购买”页面，通过侧栏入口访问；企业定制服务下方展示“套餐”和“积分充值”两个页签，支持点击及键盘切换，独立“购买账号”页签保持隐藏。个人中心的积分充值按钮仍可通过 `/purchase?tab=credits` 打开独立充值内容，提供“返回套餐”入口，刷新保留位置。购买页顶部不展示“我的积分”余额卡及快捷充值按钮，展示企业定制服务模块；套餐及充值卡片仍展示所购买的积分额度。

企业定制服务卡片按内容自适应高度，采用系统蓝色主题、浅蓝背景、蓝色边框及“联系销售”按钮。标题、说明和数据使用清晰的字号、行距与留白，文本正常换行。展示“企业定制 · 专属服务”“让品牌内容，规模化走向全球”和增长工作流说明，以及品牌与团队 1,200+、已生成视频 240万+、覆盖社媒平台数；页面不展示“示例”文案。平台数与平台标签读取现有平台配置，完整展示 TikTok、Instagram、YouTube、Facebook、X、LinkedIn，窄屏标签自动换行。联系销售复用原企业微信二维码弹窗，不创建支付订单。

套餐价格、额度和权益统一维护在 `src/services/credits.ts`，卡片、支付确认及入账均使用该来源。沿用当前分组图标权益样式，展示所支持的功能；套餐、积分充值、支付确认和成功页均不展示积分单价。不展示内部成本、利润率、旧划线价格、限时折扣、未经确认的模型或视频规格。

四档共同展示视频一键发布、全部平台、快速创作、智能创作（Agent 多任务并行）、账号数据通解、发布结果统计、项目管理（不限项目数）、产品卡创建、素材库管理。¥1,000 起展示图文一键发布、视频／图文 BGM、定时发布、爆款视频复刻、团队协作和权限管理；¥2,000 起展示批量发布、批量内容生成、内容数据分析。权益说明不增加功能权限限制，也不增加有效期、团队管理或养护执行逻辑。

每档套餐默认勾选“包含 N 个账号使用权”，可整档取消，不支持部分兑换。取消后实时使用表中仅积分额度和视频数，提示“账号已兑换为积分”，隐藏账号交付说明；重新勾选恢复含账号额度。四档独立选择，刷新恢复默认勾选；功能权益和可绑定发布账号数不随购买账号选项改变。价格相同，积分与视频数直接使用表值。

套餐卡片左上角依次展示“基础版／轻量运营”“专业版／个人运营”“商业版／多账号运营”“企业版／团队矩阵运营”，采用标题加说明的布局。套餐支付弹窗也提供同一账号选项，与卡片双向同步，实时更新到账积分；独立积分充值弹窗不显示账号选项。支付前切换会按新选择创建订单快照，已有待支付订单保持原值，支付只结算当前弹窗中的订单。支付中和成功后不可切换账号。

个人中心当前套餐按已支付套餐中最高档显示。套餐中取消账号仍购买对应版本，独立积分充值不改变套餐版本，较低档购买不覆盖已有高档；历史 ¥490 套餐记录按基础版兼容。套餐购买页对应卡片顶边显示“当前版本”，替代该卡原来的推荐标签，其他卡片保留原标签；未购买时不显示当前版本标签。未购买套餐时个人中心显示“未购买套餐”及购买入口，权益详情弹窗提示查看套餐版本。弹窗权益采用与套餐卡片相同的数据及分组展示。

独立积分充值采用表中四档仅积分配置，保留简洁卡片，不展示套餐功能权益。独立账号购买仅保留底层配置及历史订单兼容，不显示购买入口；不增加万元套餐。所有相关页面统一表述“账号使用权”。购买说明包含账号交付、平台发布及“购买套餐时，可选择是否勾选账号使用权”三点；历史名额说明保持原有内容。卡片不展示配套 IP 和账号养护次数。凭据查看及复制功能保留。

统一报价方法 getPurchaseQuote(pack, { includeAccounts }) 供页面和 createRechargeOrder 共用。账号选择参数默认含账号，新套餐订单保存 purchaseMode（withAccounts／creditsOnly）以及实际积分、账号数量和视频数快照，支付只按快照结算。仅积分订单 accountCount 为 0，不设置 deliveryMode，不产生账号交付记录；支付成功只显示积分及“完成”。历史订单即使使用相同档位标识也按原快照结算，旧 credit100 仅保留历史读取。

## 新购买自动到账

选择含账号的新订单保存 `deliveryMode: 'automatic'`。购买卡片、支付确认及购买说明均提示“美国 TikTok 账号，付款后自动到账”。支付前不增加积分或账号；演示支付完成后直接生成该订单全部账号，初始已授权、未分组，所有现有及新建项目均可使用。无需选择平台、地区或手动领取。

支付成功显示“已到账 N 个账号，已添加至账号管理”，提供“查看账号”和“关闭”。查看账号关闭弹窗并跳转账号管理；纯积分充值成功仍提供“完成”。账号来源标识为“购买账号”，详情可查看演示用户名、默认隐藏的密码、示例 IP 和美国地区，支持复制。

统一完成入口 `completePurchase` 先调用账本入账，再复用账号恢复逻辑同步工作区，积分服务不反向依赖工作区。支付状态、积分和全部账号记录在一次账本保存中写入。自动交付记录标识为 `automatic:<订单 ID>`，账号标识为 `automatic:<订单 ID>:<序号>`；保存账号所属订单、地区、凭据和示例 IP。重复支付或同步使用已保存记录，刷新不会再次充值或生成凭据。

账本保存失败时订单仍未支付，不增加积分或账号。账本成功而工作区保存失败时显示“支付已完成，账号同步失败”及“重试账号同步”。重试只补齐已保存账号，刷新或重新登录也会恢复缺失账号；已有编辑和软删除记录不会被覆盖或恢复。

## 历史订单继续领取

历史含账号订单缺少 `deliveryMode` 时（包括历史未支付订单）继续使用保存时的金额、积分、数量和原领取流程。新仅积分订单虽然也没有该字段，但账号数量为零，不产生领取余额。历史待领取账号不会自动转换；历史 `p490` 继续读取，新首档为 `p500`。

账号管理仅在历史剩余名额大于零时显示“历史待领取账号”及“领取历史账号”入口。领取可选择 TikTok、Instagram、Facebook、国家地区及数量，保留地区搜索、组合增删及校验。各组合数量须为非负安全整数，总数大于零且不超出历史余额；同平台同地区组合合并。历史领取只分配已完成历史订单，新自动到账订单不参与。新旧购买可以同时存在。

历史领取记录及地区、凭据原样保留。领取先保存记录再同步工作区，同一请求重试不重复扣减。领取失败后表单锁定，支持重试或刷新恢复。删除账号不返还历史余额，所有购买账号均跨项目可用；授权状态、项目归档及发布内容校验继续生效。

## 存储与验证

按用户保存于 `chuhai-credits-v1:<用户 ID>`、`chuhai-studio-v1:<用户 ID>`；账本兼容缺少 `claims` 的旧数据。账号详情仅为演示凭据，192.0.2.0/24 为示例 IP，不增加真实库存、代理或平台交付接口。支付仍使用支付宝／微信演示二维码及“模拟支付成功”，不会实际扣款。

验证覆盖四套餐两种选择、四独立积分档位、隐藏账号入口与键盘切换、默认充值跟随选择、订单快照、纯积分、支付前后、重复支付、刷新及用户隔离、编辑与软删除、两阶段存储失败重试、新旧订单共存、历史地区凭据保留、跨项目视频／图文发布，以及桌面和 390px 窄屏布局。

运行 `npm run typecheck`、`npm run lint`、Vitest、`recharge.spec.ts` 和 `recharge-accounts.spec.ts`，以及生产构建。本机 Node.js 25 的 Vitest 需在测试进程环境设置 `NODE_OPTIONS=--no-experimental-webstorage`，避免内置 Web Storage 覆盖 jsdom 存储；受本机目录权限影响，Vite/Vitest 使用 `--configLoader runner`。当前本地预览端口为 4184，构建后刷新即可查看。
