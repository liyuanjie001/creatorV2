# 充值与社媒帐号权益演示

个人中心顶部展示“我的积分”“定制化服务”“我购买的账号”三张卡片。桌面端积分与定制化服务并排，账号卡片在下方独占一行；窄屏依次纵向排列。充值、领取帐号和联系商务入口保持可用。

“我购买的账号”卡片正文仅显示账号数量统计。标题后的说明图标与购买卡片、支付确认及支付成功页复用同一说明，支持鼠标悬停、键盘聚焦和手机点击，再次点击、点击外部或按 Escape 关闭。卡片操作与“立即充值”共用小尺寸蓝色渐变按钮样式。

统一说明共四行：

> 购买后可选择Tiktok、Instagram、Facebook账号，覆盖100+国家地区\
> 可直接通过本平台发布视频、图文等作品\
> 帐号所有权归用户\
> 登录信息在帐号管理中查看

购买区域分为“套餐”“积分充值”“购买账号”三个页签，默认展示套餐，支持键盘切换。套餐继续沿用已确认的四档价格与到账数量。独立积分充值的模拟档位为 ¥100 / 400 积分、¥500 / 2,000 积分、¥1,000 / 4,000 积分、¥2,000 / 8,000 积分；独立帐号购买的模拟档位为 ¥99 / 1 个、¥450 / 5 个、¥850 / 10 个、¥1,600 / 20 个社媒帐号名额。购买时只确定数量，领取时选择平台与国家地区。独立充值不赠帐号，独立购买帐号不增加积分，均沿用演示支付及订单快照，付款成功只入账一次。

仅套餐卡片按顺序列出 11 项平台功能权益：视频一键发布、图文一键发布、定时发布排期、社媒帐号管理、内容数据分析、AI 视频创作、爆款视频复刻、批量内容生成、项目管理、产品卡创建、素材库管理。视频发布、图文发布和定时发布均附小写“hot”标签，使用从蓝色到紫色的渐变胶囊样式。积分充值卡片仅保留档位名称、价格、充值按钮和总积分，不展示用途说明和权益列表；购买账号卡片保留价格、购买按钮及账号信息，不展示权益列表及其分隔线。页签下方的说明文字及卡片的权益数量标题不再展示；功能的演示服务规则继续适用。

套餐和独立账号购买卡片的账号权益区展示“N 个账号”和说明图标，下方两行分别显示“可选择账号平台和国家地区”“账号所有权归用户所有”；沿用积分卡片的背景、边框、圆角、居中排版及说明文字样式。积分数量统一展示为“N 个积分”，不再显示顶部“总积分”标签。支付确认弹窗在账号数量下提示“购买后选择账号平台和国家地区”，完整四行说明继续通过图标查看。

四档套餐统一由积分服务配置：¥490（1,920 积分 / 2 个帐号）、¥1,000（4,100 / 5）、¥2,000（9,200 / 10）、¥5,000（24,245 / 20）。视频数量仍使用产品表的 147 / 315 / 707 / 1,865，不从积分反推；展示为“约可生成视频 N 个”，下一行标注“Seedance 2.0 Mini · 10s · 480P”。套餐及积分充值卡片均不展示积分单价。默认推荐 ¥2,000。

个人中心充值仍使用支付宝 / 微信演示二维码及“模拟支付成功”，不会真实扣款。完成订单一次性获得积分和帐号名额；成功页可立即领取或稍后领取。个人中心、支付成功页及帐号管理共享领取弹窗。支持 TikTok、Instagram、Facebook，与 249 个国家地区的本地清单组合领取。各平台共用地区清单，无真实库存或平台地域可用性校验。

领取表单每行选择平台、国家地区和数量，可添加或删除组合，至少保留一行；新行默认 TikTok、美国、0 个。地区选择支持中文、英文和两字母代码搜索。数量为非负安全整数，0 数量不参与交付；总数须大于 0 且不超过剩余名额。同平台、同国家地区的行合并，成功后展示组合汇总、帐号和地区。领取接口接受 `{ platform, countryCode, quantity }[]`，同时兼容旧平台数量对象（默认美国）。

帐号所有权归用户，登录信息可在帐号管理中打开帐号详情查看。套餐卡片、领取弹窗与帐号详情均展示该说明。社媒帐号权益卡片沿用积分卡片的背景、边框、圆角、尺寸和居中排版；四档充值按钮位于价格下方。

积分、名额和领取的帐号不设有效期，删除帐号不返还名额。领取帐号初始已授权、未分组，在所有现有及新建项目可直接发布；原有手动添加帐号继续要求项目关联。解绑、过期、删除、项目归档及媒体校验继续生效。

帐号详情提供演示用户名、默认隐藏的密码、示例 IP 和地区，可分别复制。帐号地区与登录信息地区使用领取所选国家地区，均标注演示；192.0.2.0/24 为示例地址，不代表真实 IP 地理归属，不提供可连接的代理。页面提示使用对应地区 IP 登录以降低平台风控风险；不检查实际网络或承诺避免风控。凭据不具备真实平台登录能力，三平台视频和图文发布均使用模拟服务。

用户数据仍保存至 `chuhai-credits-v1:<用户 ID>` 和 `chuhai-studio-v1:<用户 ID>`。新订单快照包含金额、积分、帐号数量；旧订单保持原始积分，不追补帐号权益。领取记录保存组合明细 `items`、平台分配汇总、帐号信息及所属订单；新账号保存可选的 `countryCode`。旧记录缺少新字段时仍按原数据读取和恢复，不重写旧地区或凭据。名额由完成订单减去领取数量计算。先保存领取记录，再交付帐号；交付失败期间锁定表单，使用同一请求和原始记录重试，刷新或重新登录会补齐缺失交付，不覆盖已编辑帐号，也不恢复软删除帐号。

每个帐号初始 100 积分。余额、订单及领取记录按用户隔离，重复确认付款和同一请求重复领取不重复入账。本地保存失败显示错误，不宣告成功。

验证：`npm run lint`、`npm test -- --configLoader native`、`npm run build -- --configLoader native`。浏览器验收使用 `recharge.spec.ts` 与 `recharge-accounts.spec.ts`，覆盖套餐、支付、领取、凭据、模拟发布和窄屏。

本机 Node.js 25 运行 Vitest 时，需要先在 PowerShell 中设置 `$env:NODE_OPTIONS = '--no-experimental-webstorage'`，避免 Node 内置 Web Storage 覆盖 jsdom 存储。该设置仅作用于测试进程。
