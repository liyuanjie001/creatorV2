# 充值与社媒帐号权益演示

个人中心顶部展示“我的积分”“定制化服务”“我购买的账号”三张卡片。桌面端积分与定制化服务并排，账号卡片在下方独占一行；窄屏依次纵向排列。充值、领取帐号和联系商务入口保持可用。

“我购买的账号”卡片正文仅显示账号数量统计。标题后的说明图标在悬停或键盘聚焦时展示三行文案：加粗“可直接通过本平台发布至 TikTok”、“帐号所有权归用户”、“登录信息在帐号管理中查看”。卡片操作与“立即充值”共用小尺寸蓝色渐变按钮样式。

购买区域分为“套餐”“积分充值”“购买账号”三个页签，默认展示套餐，支持键盘切换。套餐继续沿用已确认的四档价格与到账数量。独立积分充值的模拟档位为 ¥100 / 400 积分、¥500 / 2,000 积分、¥1,000 / 4,000 积分、¥2,000 / 8,000 积分；独立帐号购买的模拟档位为 ¥99 / 1 个、¥450 / 5 个、¥850 / 10 个、¥1,600 / 20 个 TikTok 帐号。独立充值不赠帐号，独立购买帐号不增加积分，均沿用演示支付及订单快照，付款成功只入账一次。独立帐号购买同样支持领取与直接发布。

仅套餐卡片按顺序列出 11 项平台功能权益：视频一键发布、图文一键发布、定时发布排期、社媒帐号管理、内容数据分析、AI 视频创作、爆款视频复刻、批量内容生成、项目管理、产品卡创建、素材库管理。视频发布、图文发布和定时发布均附小写“hot”标签，使用从蓝色到紫色的渐变胶囊样式。积分充值卡片仅保留档位名称、价格、充值按钮和总积分，不展示用途说明和权益列表；购买账号卡片保留价格、购买按钮及账号信息，不展示权益列表及其分隔线。页签下方的说明文字及卡片的权益数量标题不再展示；功能的演示服务规则继续适用。

帐号购买与领取相关页面突出“可直接通过本平台发布视频”：套餐卡片、支付确认及成功页、领取弹窗、帐号管理与详情均展示发布说明。套餐领取的 TK 帐号可直接发布至 TikTok；本平台也支持使用已绑定的对应帐号发布至 Facebook / Instagram。帐号购买范围仍为 TikTok，支付、交付与发布仍使用模拟服务。

四档套餐统一由积分服务配置：¥490（1,920 积分 / 2 个帐号）、¥1,000（4,100 / 5）、¥2,000（9,200 / 10）、¥5,000（24,245 / 20）。视频数量仍使用产品表的 147 / 315 / 707 / 1,865，不从积分反推；展示为“约可生成视频 N 个”，下一行标注“Seedance 2.0 Mini · 10s · 480P”。套餐及积分充值卡片均不展示积分单价。默认推荐 ¥2,000。

个人中心充值仍使用支付宝 / 微信演示二维码及“模拟支付成功”，不会真实扣款。完成订单一次性获得积分和帐号名额；成功页可立即领取或稍后领取。套餐仅提供 TikTok (TK) 帐号。个人中心及帐号管理共享领取弹窗，TK 数量从 0 开始，可分批领取，每次为正整数且不超过剩余名额。服务同时校验平台，新的领取请求不交付 Facebook 或 Instagram 帐号；已有领取记录和帐号保持原样，仍可恢复交付或幂等重试。

帐号所有权归用户，登录信息可在帐号管理中打开帐号详情查看。套餐卡片、领取弹窗与帐号详情均展示该说明。社媒帐号权益卡片沿用积分卡片的背景、边框、圆角、尺寸和居中排版；四档充值按钮位于价格下方。

积分、名额和领取的帐号不设有效期，删除帐号不返还名额。领取帐号初始已授权、未分组，在所有现有及新建项目可直接发布；原有手动添加帐号继续要求项目关联。解绑、过期、删除、项目归档及媒体校验继续生效。

帐号详情提供演示用户名、默认隐藏的密码、示例 IP 和地区，可分别复制。默认地区为美国；192.0.2.0/24 为示例地址，不提供可连接的代理。页面提示使用对应地区 IP 登录以降低平台风控风险；不检查实际网络或承诺避免风控。凭据不具备真实平台登录能力。

用户数据仍保存至 `chuhai-credits-v1:<用户 ID>` 和 `chuhai-studio-v1:<用户 ID>`。新订单快照包含金额、积分、帐号数量；旧订单保持原始积分，不追补帐号权益。领取记录保存平台分配、帐号信息及所属订单，名额由完成订单减去领取数量计算。先保存领取记录，再交付帐号；交付失败可用同一请求重试，刷新或重新登录会补齐缺失交付，不覆盖已编辑帐号，也不恢复软删除帐号。

每个帐号初始 100 积分。余额、订单及领取记录按用户隔离，重复确认付款和同一请求重复领取不重复入账。本地保存失败显示错误，不宣告成功。

验证：`npm run lint`、`npm test -- --configLoader native`、`npm run build -- --configLoader native`。浏览器验收使用 `recharge.spec.ts` 与 `recharge-accounts.spec.ts`，覆盖套餐、支付、领取、凭据、模拟发布和窄屏。

本机 Node.js 25 运行 Vitest 时，需要先在 PowerShell 中设置 `$env:NODE_OPTIONS = '--no-experimental-webstorage'`，避免 Node 内置 Web Storage 覆盖 jsdom 存储。该设置仅作用于测试进程。
